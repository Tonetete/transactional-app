# infra: Terraform

Replaces `apps/infra` (AWS CDK), which stays until the migration is complete (`odd/tasks/terraform-migration.md`).

```
infra/
  modules/   network, messaging, database   (settlement, compute, provisioning, web_hosting follow)
  envs/
    aws/     real AWS: remote S3 state, data protected
    floci/   local emulator: endpoint on every service, disposable data
```

A module describes one concern and exposes only what its consumers need. The CDK `local` flag is replaced by explicit
inputs; today that is `protect_data` (deletion protection, final snapshot, secret recovery window).

## Floci
```bash
cd infra/envs/floci
terraform init && terraform apply     # names are acex-floci-*, so they coexist with the CDK stack
terraform destroy
```
Resource names include `<project>-<environment>`; the CDK stack uses different names, so both can live in one floci.
Verified on floci 2.3.0: apply (38 resources, ~1.5 min), an empty second plan, and a clean destroy.

## Tests
`terraform test` runs against mocked providers (no floci needed), one file per module:
```bash
for m in infra/modules/*; do (cd $m && terraform init -backend=false >/dev/null && terraform test); done
```

## Notes
- Database passwords are generated by Terraform, so they are in the state. The AWS state bucket must be private,
  encrypted and versioned.
- floci reports security-group references as `000000000000/sg-...`, which makes Terraform plan a permanent in-place change
  on rules that reference another security group. The compute module will work around it.
